# S3 Blocking and Candidate Generation

The S3 blocking process generates candidate entity pairs between Source 1 (S1) and Source 3 (S3). It reduces the number of possible entity comparisons by applying multiple blocking rules based on country, business names, and addresses. This helps identify potential matches efficiently for the next stage of entity resolution.

**Notebook:** [S3_Blocking.ipynb](https://github.com/Yaazhini-R/amazon-ml-challenge-2026/blob/main/S3_Blocking/S3_Blocking.ipynb)

The blocking process uses different rules to generate candidate pairs and evaluates their ability to retrieve known matching entities using the available ground-truth data.

### Analysis Performed

- **Name and Address Prefix Blocking:** Generated candidate pairs using country, the first four characters of normalized business names, and the first four characters of normalized addresses.
- **Exact Name Blocking:** Identified candidate pairs with the same country and exact normalized business name.
- **Name Token Blocking:** Generated candidate pairs using shared business name tokens within the same country, excluding tokens appearing in more than 1,000 S3 entities.
- **Combined Blocking Rules:** Combined the candidate pairs generated by the three selected rules to improve ground-truth match coverage.
- **Recall Evaluation:** Evaluated each blocking rule and the combined strategy against known ground-truth matches.
- **Candidate Pair Generation:** Generated candidate pairs for downstream entity matching.
- **Additional Rule Evaluation:** Tested a six-character name prefix rule and excluded it from the final strategy because it did not provide a meaningful improvement.

### Results

- **S1 Entity Records:** 2,206,821
- **Total Ground-Truth Pairs:** 3,944,746
- **Combined Ground-Truth Recall:** 71.58%
- **Ground-Truth Pairs Captured:** 2,823,657
- **Ground-Truth Pairs Missed:** 1,121,089
- **Candidate Pairs Generated:** 527,901,663
- **Average Candidates per S1 Entity:** 239.21

### Purpose

This process helps reduce the search space for entity matching while retaining a large proportion of known matching pairs. The generated candidates will be used in subsequent entity resolution stages, where matching methods can evaluate and identify the most likely entity matches. The combined blocking strategy achieved 71.58% recall on the available ground-truth pairs.

### Output

The candidate generation process produces a TSV file containing the `source1_entity_id` and `source3_entity_id` columns. The large candidate output and supporting blocking index are maintained in the working environment rather than uploaded to GitHub.
